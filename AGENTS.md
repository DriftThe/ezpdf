# AGENTS.md

ezpdf — a Tauri 2 desktop **real-time PDF translation reader** for Windows, built with Vue 3 + TypeScript + Vite. See `PLAN.md` for the approved architecture and phased plan (OCR via an in-repo Python FastAPI service, LLM translation, Rust-side scheduling; both reader panes are self-drawn with `pdfjs-dist` — do not reintroduce pdf-vue3). Current state: UI skeleton + real repo IPC, no mock data. Repo model = `.ezrepo` flat index (`{folders, pdfs[]}`, pretty JSON; each entry `{id, name, bind, belong}` — `id` is a content-hash stable unique key generated at import time, the key for all frontend lookups; `bind` = bound-JSON repo-relative path). Multi-file import via `import_pdf` (best-effort, returns `ImportOutcome {imported, failed}`; copies PDFs in as `<name>-<id>.pdf` + skeleton `<name>-<id>.json`, rejects duplicate content by hash). Repo mutations (2026-09-14): `create_folder`/`delete_folder`/`delete_pdf`/`move_pdf` return the updated `RepoTree` (frontend applies it in place — no refresh command anymore); folders are **logical** (`belong` label only, nothing on disk), so `move_pdf(belong=null)` = move out to root and `delete_folder` **cascades** (deletes the folder's PDFs + bind JSONs — the confirm dialog says so); the sidebar's 新增文件夹 button replaced the old 刷新仓库 button and RepoTree row menus (hover) drive move/delete (delete confirms via the in-app `ConfirmDialog.vue` + `composables/confirm.ts`, **not** plugin-dialog anymore). The chosen repo is persisted (`repo` key in config.json) and auto-opened on launch (`library.openLastRepo()`, clears the path when it fails); 导入 PDF/新增文件夹 are disabled with no repo, and the sidebar footer has a 选择 button to re-pick. **Bound JSON is the user-defined single source of truth** for parse state: `{status: "Pending"|"Processing"|"Finished", pages: [{index (1-based), finished, translated, blocks: [{type, content, loc: [x1,y1,x2,y2] corners in pt, translation}]}]}`. Import pre-fills the pages skeleton (index 1..N, `finished/translated: false`, empty `blocks`; N is parsed from the bytes via lopdf — parse failure (e.g. encrypted PDF) falls back to `pages: []` and the reason surfaces through `ImportOutcome.warnings` in the import toast). `translation: null` does NOT mean hidden — it means render `content` as-is: the LLM returns null when it judges the translation to be the same language as the source; `translated` marks the LLM pass done for that page (serde default false → old JSONs auto-backfill translation). Translation-pane overlay rule (user-decided 2026-09-11; formula added 2026-09-12; footer/vision_footnote added 2026-09-14): `src/lib/blocks.ts` OVERLAY_TYPES = TRANSLATED_TYPES (text/paragraph_title/doc_title/abstract/aside_text/footnote/footer/vision_footnote/figure_title/content) + formula get a white-bg overlay box showing `translation ?? content` (bypass stage → original content); all other types (table/chart/image/number/header/seal/algorithm/reference/reference_content) get NO overlay — original PDF pixels show through, their OCR content lives only in the bound JSON; overlay font size auto-fits the box (binary-search largest fitting size, fill without overflow) via the `v-fit` directive in PageCard.vue; formula covers are vertically centered with the KaTeX display margins trimmed (`.cover-formula` — KaTeX's default 1em margins otherwise eat a ~16pt formula box and shrink the fit). Stage-2 rendering shipped: pdfjs-dist v6 canvas pages (self-virtualized), asset-protocol fetch, real page count/geometry, fit-width zoom; translation pane shows EmptyState while `bind === null || status === "Pending"`. Settings are a full-page overlay (not a modal); repo-tree rows are intentionally large (~1.3x default). Zoom is viewport-anchored (`ReaderPane.vue` captures the midpoint page + in-page fraction before zoom/geometry reflows and restores it after; `overflow-anchor: none` so the browser's native anchoring doesn't fight it — zoom no longer jumps pages). Cover text padding scales with box size (small boxes keep usable font sizes). Linux/system-proxy story aside, the app ships a self-drawn window chrome (2026-09-14): `decorations: false`, a 34px `TitleBar.vue` carrying only the `ezpdf` wordmark, the light/dark/system theme toggle and minimize/maximize/close (drag via `data-tauri-drag-region`, double-click maximizes, red hover on close; window defaults to 1600×1022). Theme is `general.theme` (persisted; applied by `composables/theme.ts` through `:root[data-theme]` with a temporary `.theme-switching` color fade — light is blue-white, and `index.html` pre-applies a localStorage mirror to avoid a first-paint flash). Startup defaults to **paused** (toolbar shows 启动翻译) unless both 自动唤醒 OCR and 自动续跑 are on. LLM settings verify button probes connectivity and auto-detects the thinking-off parameter strategy (`thinkingOff` persisted); the model field auto-fetches `/models` **on click only**; GitHub releases are checked at launch (silent) and via 常规 → 检查更新.

## Commands

Package manager is **pnpm** (no lint or test scripts exist yet).

- `pnpm dev` — Vite dev server only (frontend in browser); first runs `scripts/copy-pdfjs-assets.mjs`
- `pnpm build` — typecheck + build (`vue-tsc --noEmit` + copy script + `vite build`); this is the typecheck command
- `pnpm tauri dev` — full desktop app dev (starts Vite automatically via `beforeDevCommand`)
- `pnpm tauri build` — release build/bundle (Rust release profile uses LTO, strip, panic=abort); `beforeBuildCommand` also runs `scripts/pack-runtime.mjs` (stages the bundled Python + pyserver + prompts into `src-tauri/resources/`, cached across builds — set `EZPDF_PYTHON_PKG` if the download is unavailable)
- Rust checks: run `cargo check` / `cargo build` inside `src-tauri/`; `cargo test` also regenerates ts-rs bindings

## Architecture

Two halves, communicating only through Tauri's IPC:

- `src/` — Vue 3 frontend (`<script setup>` SFCs). Entry `src/main.ts` (installs Pinia); app shell is `src/components/shell/AppShell.vue`. UI state lives in Pinia stores under `src/stores/` (library/reader/parse/settings); domain types mirror the Rust serde structs via ts-rs bindings re-exported in `src/types/domain.ts`.
- Rendering pipeline (stage 2): import pdfjs ONLY via `src/lib/pdfjs.ts` (worker setup + `openPdf()` which injects the runtime resource paths — cMaps/standard fonts/wasm/ICC; skipping them breaks CJK text and non-embedded standard fonts). `src/composables/usePdfDoc.ts` caches one `PDFDocumentProxy` per pdf id; `ReaderArea.vue` owns the doc lifecycle (load / destroy / switch-race guards). Page-list truth = pdfjs `numPages` (reader store `pageCount` falls back to bound-JSON `pages.length`); card geometry is per-page real (`reader.pageSizeFor(n)`, measured in background chunks by ReaderArea after doc ready — scan PDFs often have a different size on every page, so overlays must divide loc by the SAME per-page viewport the OCR capture used; page-1-based assumption caused whole-page misalignment, fixed 2026-09-11); the bound JSON supplies only OCR block overlays (`PdfPageCard`/`PdfPageCanvas` self-virtualize via IntersectionObserver). Original-pane block rects are hover targets: a translated block pops a teleported rich-text card (`hover-preview`, fixed follow-cursor; `above` flips upward in the lower viewport half) — deliberately NOT a `title` attribute (user 2026-09-14). PDF binaries never travel through invoke — the frontend fetches `convertFileSrc(pdfPath)` asset URLs.
- Settings (`src/components/settings/`): `SettingsPage.vue` is an absolute overlay in `AppShell` (z-10) covering sidebar+reader with `v-show` — nothing underneath unmounts; the top toolbar (z-20, height `--toolbar-h`) stays visible. Sections are registered in the `SECTIONS: Record<SettingsSection, ...>` map — extending the union without registering is a build error (`llm`/`ocr`/`common`; the old 解析 pane is gone — its concurrency fields were dead and its resume switch moved into 常规). Per-section components live in `settings/sections/` (pure markup, no scoped CSS; root element uses `set-pane`), state lives in the settings store, back button = save-and-exit (no per-pane save buttons and **no success toast** — the page just closes; save = `save_settings` writes pretty JSON to `config.json` = repo root in dev / **app directory (beside the exe) in production** — and closes; the store `ensureLoaded()` reads it once at startup AFTER the dev-only `auth.cfg` fill so persisted values win; malformed sections are ignored field-by-field; legacy `ocr.autoLaunch`/`parse.resumeOnStart` keys migrate to `general`). 常规 holds 启动时自动唤醒 OCR 服务 (`general.autoLaunch`) and 启动时自动续跑 (`general.resumeOnStart`): `AppShell` onMounted sets `parse.paused = true` unless BOTH are on, then `parse.autoStartIfEnabled()` probes env and only calls `ocr_start` when Python/deps/models are all present (log line instead of a crash loop otherwise), plus 检查更新 (`check_update` → GitHub releases of DriftThe/ezpdf; launch check is silent, manual toasts errors). Shared form classes `.set-pane/.set-title/.set-field/.set-field-row/.set-check/.set-hint/.set-button` are global in `main.css` (`set-` prefix, don't combine `.set-button` with `.btn`). LLM pane: API Key row has a 验证 button (`verify_llm` → connectivity + thinking-off probe, writes `llm.thinkingOff`; strategy `none` warns), model input is a datalist fed by `fetch_llm_models` (auto-try once per session, toast on error).
- `src-tauri/` — Rust backend. `src-tauri/src/pyenv.rs` owns ALL pyserver path resolution (the single dev/prod branch point, `cfg(dev)` compile-time + `EZPDF_TOOLKIT_ROOT`/`EZPDF_PYTHON_EXE`/`EZPDF_MODELS_DIR` runtime overrides; resolved once in the `setup` hook and stored as global `PyPaths` state) plus the environment layer: `probe_blocking()` runs `pyserver/bootstrap.py` (pure-stdlib probe → one-line stdout JSON contract in PLAN-pyserver.md §6) with the bundled python (prod, `<install>/python/python.exe`) or the dev venv / discovered system python (`py -3` → `PATH python`); models live outside the install dir in prod (`~/.ezpdf/models`, so upgrades don't re-download 1.9GB). `install_env(mode, use_mirror)` is the one-click service install (user 2026-09-14): returns `Ok(true)` and does nothing when deps are complete and the torch build already satisfies the pick (CUDA ⊂ CPU — a cuda env answers a cpu request, never the reverse); GPU mode aborts up front when `nvidia-smi` is missing, otherwise base requirements → torch variant chosen by the dropdown (installed-cuda skips reinstall), streaming both pip streams to `ocr://log` plus staged progress (`ocr://install` {phase, percent}, mirrored to frontend) — the mirror switch swaps in TUNA pypi + SJTU pytorch-wheels for the official indexes (`pip --retries 6 --timeout 60`; TUNA has dropped a download mid-flight). `download_models(use_mirror)` adds the model layer: `requirements-download.txt` (huggingface_hub only, installed on demand — idempotent pip) → `python -m app.fetch`, which snapshot-downloads the missing models (`PaddlePaddle/PP-DocLayoutV3_safetensors`, `PaddlePaddle/PaddleOCR-VL-1.6`) through `hf-mirror.com` (mirror on) or `huggingface.co` (off) into `EZPDF_MODELS_DIR` — skip-if-complete with the same completeness contract as bootstrap, resumable by the hub library. `src-tauri/src/pyserver.rs` owns the service lifecycle state machine (`supervise`: spawn `python -m app.main` → wait `EZPDF_READY {port,pid}` stdout line (60s) → `/health` with the per-spawn session token → connected; crash → exponential-backoff restart, 3 consecutive → `failed` terminal; stop = drop the held child stdin → Python's stdin-EOF watchdog self-exits). Production packaging: `scripts/pack-runtime.mjs` stages a relocatable python-build-standalone 3.12 (bare, pip only) + pyserver code + system_prompt into `src-tauri/resources/` (mirror chain NJU → ghfast → GitHub; cache + `EZPDF_PYTHON_PKG` override; bsdtar explicitly, PATH tar may be MSYS GNU tar) and hard-fails if `dist/` contains the `auth.cfg` apiKey; `tauri.conf.json` maps `resources/*` into the install root (`bundle.resources` targets are relative to the resource dir → `$INSTDIR/python` etc. — exactly what prod `PyPaths` probes first, falling back to a `resources/` subdir), NSIS only, `installMode: currentUser` so pip can write the install dir. Commands registered in `generate_handler![]`: `check_and_build_repo`, `gettree_from_config`, `load_pdf`, `import_pdf`, `create_folder`, `delete_folder`, `delete_pdf`, `move_pdf`, `load_settings`, `save_settings`, `ocr_env_report`, `ocr_install_env`, `ocr_download_models`, `ocr_start`, `ocr_stop`, `verify_llm`, `fetch_llm_models`, `check_update`; events `ocr://status` (payload = ServiceStatus string), `ocr://log`, `ocr://install` (InstallProgress) and `llm://log` (translation-chain log → rendered at the bottom of the LLM settings pane). Invoked from the frontend with `invoke("command_name", {...})` from `@tauri-apps/api/core`. Command args are camelCase in JS and snake_case in Rust; serde structs serialize **camelCase** as well (the TS field is `pdfPath`, not `pdf_path`).
- OCR scheduling bridge (stage 4 批3; decoupled translation 2026-09-14): the parse store drives the loop entirely frontend-side — single `tick()` = pick book (focused first; per-book `load_pdf` reads bind JSON status/finished/translated flags, no parse_progress command) → ring-collect ≤4 unfinished pages (focused book starts at `reader.currentPage`, others at 1) → `src/lib/pageCapture.ts` offscreen render (PNG b64, scale 2.0) → invoke `parse_pdf` (OCR only — it no longer waits for translation) → per-book translation chain: `queueTranslate` fire-and-forgets `translate_pdf` for the just-OCR'd pages (same book serializes, Rust runs stride-2 phases internally), so the next OCR batch starts immediately. Results patch `library.pdfs[id].pages` for the focused book (translation pane updates reactively; background books have no store cache — Rust's atomic tmp+rename batch write is the truth, next round re-reads via load_pdf). The chain self-continues via queueMicrotask after each batch; nothing processable → `standing` suspends; wakes fire from library.selectPdf / importPdf success / loadRepo / serviceStatus→connected watch / unpause / prefill completion / a drained translation chain with untranslated pages left. Batch failure: per-book strike map, 3 strikes = skip that book until next wake. `parse.paused` (toolbar 暂停翻译/启动翻译) gates the whole loop: `tick()` via `isRunnable()` and `queueTranslate`/its `run` refuse new submissions while paused (in-flight invoke finishes; resume via `togglePaused` → `wake`). `usePdfDoc` is LRU≤2 with a pin for the focus book (never evicted); background books reuse the same per-id cache. Books with empty pages (lopdf parse failure) are skipped until opened — geometry-ready watch backfills via `prefill_pages` then wakes. Non-Tauri browser mode (`pnpm dev` without Tauri): silently inert.
- LLM translation (stage 4 批4, 2026-09-14): spec/decisions in `PLAN-LLM.md`. `src-tauri/src/translate.rs` is the OpenAI-compatible client + smart-context agent loop: per page it packs TRANSLATED_TYPES blocks (non-empty content, `translation == null`) into protocol A, allows ONE `need_context` round (context C from the neighbour page's boundary ≤3 blocks, before=tail/after=head), validates `result` 1:1 by index (A=null = same-language), and binds a valid `external`/`external_index` back onto the neighbour page's block (that box is then skipped on its own page via `translation != null`; fallback format B or a bad index touches nothing). Thinking is disabled per provider (zen: `reasoning.enabled=false` + `reasoning_effort=none`; SiliconFlow: `enable_thinking=false` + `thinking.type=disabled`; matrix in PLAN-LLM.md §5). `parse_batch` is OCR-only (one atomic write) — the parse store chains `translate_pdf` per OCR batch; `translate_pdf` runs stride-2 phases (positions 0,2,4… then 1,3,5…, so neighbouring pages never translate concurrently) with per-page tasks on snapshots (`build_task`/`translate_task`/`apply_done`) over `tauri::async_runtime::spawn`, then re-reads the JSON under the per-book file lock (`FILE_LOCKS` in `parse.rs`; network/LLM calls stay outside the lock) and merges. System prompt = `<prompt dir>/intelli_context.md` for smart mode, `standard_translate.md` for `smartContext` off (no context protocol at all; result items use `content` — the parser accepts both `A` and `content`, and non-smart tasks ignore any stray `need_context`; `{{target_language}}` templated at load; if the placeholder is missing the target language is appended — user 2026-09-14; `EZPDF_SYSTEM_PROMPT_DIR` overrides the dir — the one place to change for packaging; prod resolves it from the bundled `system_prompt/` resource). Thinking-off is a persisted strategy (`llm.thinkingOff`: `auto` = URL matrix, `reasoning`/`enable_thinking`/`thinking_type` explicit, `none` = plain) discovered by the LLM pane's 验证 button (`verify_llm` probes with a short prompt and checks `reasoning_content`/`reasoning`/empty content; if nothing works it warns 无法关闭思考模式 and stores `none`). LLM config arrives per-invoke from the settings store, dev-filled from gitignored root `auth.cfg` via a Vite raw import (`loadAuthCfg` in `src/stores/settings.ts`, dev-only; `pack-runtime.mjs` additionally greps `dist/` for the key and aborts the build if found); reqwest needs `rustls-tls` + `system-proxy` (defaults are off — the system proxy is how region-restricted endpoints are reached, and `ProxyOverride` keeps local pyserver direct); opencode zen endpoints also get an `x-opencode-session` routing header scoped by URL (see PLAN-LLM.md §5). Custom reasoning: 提示词协议改动要与 `translate.rs` 的解析同步。
- `src-tauri/bindings/` — ts-rs generated by `cargo test`; never hand-edit, and delete stale files when a type is removed.
- `src-tauri/capabilities/default.json` — permission allowlist. New Tauri plugin APIs won't work until their permissions are added here.
- `src-tauri/gen/` — generated schemas; never hand-edit.

## Gotchas

- **Port 1420 is strict** (`vite.config.ts`): Vite fails if it's taken, and `tauri.conf.json` points `devUrl` at it. HMR uses 1421 when `TAURI_DEV_HOST` is set.
- **`testfiles/` is gitignored** and reserved for manual-test PDFs (text+table+formula+image). It is no longer referenced by code; the reader renders PDFs from the library store (real repo data via IPC only — mock data was removed).
- **Asset protocol** (`tauri.conf.json` → `security.assetProtocol`): enabled with an intentionally **empty static scope**; `gettree_from_config` grants the repo root at runtime via `asset_protocol_scope().allow_directory(root, true)` (least privilege). Requires the `protocol-asset` cargo feature on `tauri` (already set). If a render shows "PDF 加载失败", suspect a missing scope grant first.
- **pdfjs v6 API breaks**: `PDFDocumentProxy.destroy()` no longer exists — release via `doc.loadingTask.destroy()`; `page.render()` requires `canvas` (not just `canvasContext`).
- **pdfjs runtime assets** (`cmaps`/`standard_fonts`/`wasm`/`iccs`) are copied to `public/pdfjs/` by `scripts/copy-pdfjs-assets.mjs` (runs at the start of `pnpm dev`/`pnpm build`). `public/pdfjs/` is gitignored — regenerated on first dev/build, never hand-edit. Without them CJK text renders misplaced/missing.
- Vite is configured to not watch `**/src-tauri/**` — Rust changes require restarting `pnpm tauri dev`.
- Windows dev machine: the Rust lib is named `ezpdf_lib` (with `_lib` suffix) to avoid a Windows bin/lib name conflict — keep the suffix.
- TypeScript is strict with `noUnusedLocals`/`noUnusedParameters`; unused imports will fail `pnpm build`.
- No CSP is set (`"csp": null` in `tauri.conf.json`) — fine for dev; if a CSP is added later, pdfjs needs `worker-src` for its module worker.
- The build warning about a >500 kB chunk is expected (pdfjs-dist is large); code-split later if it matters.
- Legacy hand-written test entries in a repo (files not named `<name>-<id>.pdf`) will fail to load/render by design — re-import them.
- Running `vite` directly (not via `pnpm dev`/`pnpm build`) skips the pdfjs asset copy — a fresh clone then misses `public/pdfjs/` and CJK rendering degrades (404s in console, no crash).
- **pyserver/** is the ported Wise-Paddle OCR service host (stage 2.5; decisions in PLAN-pyserver.md §2.1). Single-instance pipeline (`PP-DocLayoutV3` + `PaddleOCR-VL-1.6` in `app/services/pipeline.py`, lazy-loaded + `threading.Lock`) — concurrency containers (Pool/Scheduler/vouchers) were deliberately degenerated away; don't reintroduce them. `models/` is a direct copy of Wise-Paddle's model dir (1.9GB, gitignored) but is not a hard prerequisite — on a fresh host `app/fetch.py` (`python -m app.fetch`, invoked by `ocr_download_models`) downloads the missing repos via hf-mirror with resume; completeness = config.json + preprocessor_config.json + any weight file (same contract as bootstrap.py). `requirements-download.txt` is `huggingface_hub` only, installed on demand. `requirements.txt` is a verified-minimal set; the four non-obvious pins are load-path requirements, not optional: `protobuf` (SentencePieceExtractor; without it the VL tokenizer is misdetected as a tiktoken file and fails to parse), `sentencepiece` + `tiktoken` (PaddleOCR-VL tokenizer), `opencv-contrib-python` (PP-DocLayoutV3 post-processing). The VL tokenizer loads without `trust_remote_code` — the rope patch in `pipeline.py` (ported, module-level side effect) must stay. Layout detection is multi-pass add-only (`LayoutDetector.detect`): main pass unchanged at threshold 0.5, then a sharpened pass at 0.45 merges text-family candidates, then sharpened top/bottom half-page tiles at 0.38 (header/footer also allowed) merge more — fixes systematic misses of small/spaced text under pdfjs rendering (pdfium renders score ~0.1-0.15 higher on the same line; full-page squash to 800x800 compresses tall pages, tiles undo it; tuned 2026-09-12, see PLAN-OCR.md §8.4; candidates must pass IoU ≤0.3 and containment ≤0.6 against existing boxes; `BoxFilter.min_score` is 0.35 to let them through; all model forwards are chunked to ≤4 images because batch=8 hits a slow kernel). `BoxFilter.filter` also drops 大框套小框 duplicates (user 2026-09-14): after NMS, a box substantially contained (≥60% of its area, `contain_threshold`) in an already-kept larger box is discarded — NMS can't catch nesting because IoU is tiny.
- `parse.ts` store: `serviceStatus` (incl. `failed`) is driven by the `ocr://status` event, `envReport`/`envLogs` by `ocr_env_report`/`ocr://log`, `installProgress` by `ocr://install`, `llmLogs` by `llm://log` (Rust `translate::log` + frontend `[ui]` 调度日志；LLM 设置页底部 `log-box`）；the OCR settings pane's five lights (Python/CUDA/环境/模型/服务) derive from these — don't add separate probe commands. `installService(mode, useMirror)` chains `ocr_install_env` (bool = 已安装跳过) → `ocr_download_models` only when models are missing (`installing` guards reentry).
- Frontend `listen()` subscriptions in `parse.ts` reject silently outside the Tauri runtime (plain `pnpm dev` browser mode) — keep the `.catch(() => undefined)`.

## 版本与发布

版本唯一真相源 = `src-tauri/tauri.conf.json` 的 `"version"`（安装包名、`app.package_info()`、前端 `getVersion()`、更新检查全部读它）。

1. **改版本**：编辑 `src-tauri/tauri.conf.json` → `"version": "0.2.0"`（可选同步 `package.json` 便于 npm 侧识别；`Cargo.toml` 的 version 不参与打包）。
2. **构建**：仓库根执行 `pnpm tauri build`。自动执行：`vue-tsc` 类型检查 → `vite build` → `scripts/pack-runtime.mjs`（随包 Python/pyserver/提示词，已缓存则秒过；改 Python 版本需删 `src-tauri/resources/.runtime-stamp` 或 `--force`）→ Rust release（LTO）→ NSIS 打包。
3. **产物**：`src-tauri/target/release/bundle/nsis/ezpdf_<version>_x64-setup.exe`（约 30MB；首次运行后在应用内「一键安装服务」下载依赖与模型）。
4. **分发**：把 setup.exe 传到 GitHub Releases，tag 用 `v<version>`（如 `v0.2.0`）——应用内「检查更新」查 `DriftThe/ezpdf` 的 latest release 并按 tag 比数字版本。
5. **注意**：安装包未签名（用户首次运行会有 SmartScreen 提示，需代码签名证书才能消除）；`pack-runtime.mjs` 会在构建时校验 `dist/` 不含 `auth.cfg` 的 apiKey，发现即中止构建。
