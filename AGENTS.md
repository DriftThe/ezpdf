# AGENTS.md

ezpdf — a Tauri 2 desktop **real-time PDF translation reader** for Windows, built with Vue 3 + TypeScript + Vite. See `PLAN.md` for the approved architecture and phased plan (OCR via an in-repo Python FastAPI service, LLM translation, Rust-side scheduling; both reader panes are self-drawn with `pdfjs-dist` — do not reintroduce pdf-vue3). Current state: UI skeleton + real repo IPC, no mock data. Repo model = `.ezrepo` flat index (`{folders, pdfs[]}`, pretty JSON; each entry `{id, name, bind, belong}` — `id` is a content-hash stable unique key generated at import time, the key for all frontend lookups; `bind` = bound-JSON repo-relative path). Multi-file import via `import_pdf` (best-effort, returns `ImportOutcome {imported, failed}`; copies PDFs in as `<name>-<id>.pdf` + skeleton `<name>-<id>.json`, rejects duplicate content by hash). **Bound JSON is the user-defined single source of truth** for parse state: `{status: "Pending"|"Processing"|"Finished", pages: [{index (1-based), finished, blocks: [{type, content, loc: [x1,y1,x2,y2] corners in pt, translation}]}]}`. Import pre-fills the pages skeleton (index 1..N, `finished: false`, empty `blocks`; N is parsed from the bytes via lopdf — parse failure (e.g. encrypted PDF) falls back to `pages: []` and the reason surfaces through `ImportOutcome.warnings` in the import toast). `translation: null` does NOT mean hidden — it means render `content` as-is: at stage 4 the LLM returns null when it judges the translation to be the same language as the source; this contract is documentation-only, not implemented in code. Translation-pane overlay rule (user-decided 2026-09-11; formula added 2026-09-12): `src/lib/blocks.ts` OVERLAY_TYPES = TRANSLATED_TYPES (text/paragraph_title/doc_title/abstract/aside_text/footnote/figure_title/content) + formula get a white-bg overlay box showing `translation ?? content` (bypass stage → original content); all other types (table/chart/image/number/header/footer/seal/algorithm/reference/reference_content) get NO overlay — original PDF pixels show through, their OCR content lives only in the bound JSON; overlay font size auto-fits the box (binary-search largest fitting size, fill without overflow) via the `v-fit` directive in PageCard.vue. Stage-2 rendering shipped: pdfjs-dist v6 canvas pages (self-virtualized), asset-protocol fetch, real page count/geometry, fit-width zoom; translation pane shows EmptyState while `bind === null || status === "Pending"`. Settings are a full-page overlay (not a modal); repo-tree rows are intentionally large (~1.3x default).

## Commands

Package manager is **pnpm** (no lint or test scripts exist yet).

- `pnpm dev` — Vite dev server only (frontend in browser); first runs `scripts/copy-pdfjs-assets.mjs`
- `pnpm build` — typecheck + build (`vue-tsc --noEmit` + copy script + `vite build`); this is the typecheck command
- `pnpm tauri dev` — full desktop app dev (starts Vite automatically via `beforeDevCommand`)
- `pnpm tauri build` — release build/bundle (Rust release profile uses LTO, strip, panic=abort)
- Rust checks: run `cargo check` / `cargo build` inside `src-tauri/`; `cargo test` also regenerates ts-rs bindings

## Architecture

Two halves, communicating only through Tauri's IPC:

- `src/` — Vue 3 frontend (`<script setup>` SFCs). Entry `src/main.ts` (installs Pinia); app shell is `src/components/shell/AppShell.vue`. UI state lives in Pinia stores under `src/stores/` (library/reader/parse/settings); domain types mirror the Rust serde structs via ts-rs bindings re-exported in `src/types/domain.ts`.
- Rendering pipeline (stage 2): import pdfjs ONLY via `src/lib/pdfjs.ts` (worker setup + `openPdf()` which injects the runtime resource paths — cMaps/standard fonts/wasm/ICC; skipping them breaks CJK text and non-embedded standard fonts). `src/composables/usePdfDoc.ts` caches one `PDFDocumentProxy` per pdf id; `ReaderArea.vue` owns the doc lifecycle (load / destroy / switch-race guards). Page-list truth = pdfjs `numPages` (reader store `pageCount` falls back to bound-JSON `pages.length`); card geometry is per-page real (`reader.pageSizeFor(n)`, measured in background chunks by ReaderArea after doc ready — scan PDFs often have a different size on every page, so overlays must divide loc by the SAME per-page viewport the OCR capture used; page-1-based assumption caused whole-page misalignment, fixed 2026-09-11); the bound JSON supplies only OCR block overlays (`PdfPageCard`/`PdfPageCanvas` self-virtualize via IntersectionObserver). PDF binaries never travel through invoke — the frontend fetches `convertFileSrc(pdfPath)` asset URLs.
- Settings (`src/components/settings/`): `SettingsPage.vue` is an absolute overlay in `AppShell` (z-10) covering sidebar+reader with `v-show` — nothing underneath unmounts; the top toolbar (z-20, height `--toolbar-h`) stays visible. Sections are registered in the `SECTIONS: Record<SettingsSection, ...>` map — extending the union without registering is a build error. Per-section components live in `settings/sections/` (pure markup, no scoped CSS; root element uses `set-pane`), state lives in the settings store, back button = save-and-exit (no per-pane save buttons). Shared form classes `.set-pane/.set-title/.set-field/.set-field-row/.set-check/.set-button` are global in `main.css` (`set-` prefix, don't combine `.set-button` with `.btn`).
- `src-tauri/` — Rust backend. `src-tauri/src/pyenv.rs` owns ALL pyserver path resolution (the single dev/prod branch point, `cfg(dev)` compile-time + `EZPDF_TOOLKIT_ROOT` override; resolved once in the `setup` hook and stored as global `PyPaths` state) plus the environment layer: `probe_blocking()` runs `pyserver/bootstrap.py` (pure-stdlib probe → one-line stdout JSON contract in PLAN-pyserver.md §6) with the venv python or a discovered system python (`py -3` → `PATH python`), and `install_env()` orchestrates venv creation → base requirements → torch variant (`requirements-torch-cuda.txt` when nvidia-smi reports driver CUDA major ≥13, else `requirements-torch-cpu.txt`), streaming both pip streams to the `ocr://log` event. `download_models()` adds the model layer: `requirements-download.txt` (huggingface_hub only, installed on demand — idempotent pip) → `python -m app.fetch`, which snapshot-downloads the missing models (`PaddlePaddle/PP-DocLayoutV3_safetensors`, `PaddlePaddle/PaddleOCR-VL-1.6`) through the `hf-mirror.com` endpoint (default, overridable via `HF_ENDPOINT`) into `EZPDF_MODELS_DIR` — skip-if-complete with the same completeness contract as bootstrap, resumable by the hub library. `src-tauri/src/pyserver.rs` owns the service lifecycle state machine (`supervise`: spawn `python -m app.main` → wait `EZPDF_READY {port,pid}` stdout line (60s) → `/health` with the per-spawn session token → connected; crash → exponential-backoff restart, 3 consecutive → `failed` terminal; stop = drop the held child stdin → Python's stdin-EOF watchdog self-exits). Commands registered in `generate_handler![]`: `check_and_build_repo`, `gettree_from_config`, `load_pdf`, `import_pdf`, `ocr_env_report`, `ocr_install_env`, `ocr_download_models`, `ocr_start`, `ocr_stop`; events `ocr://status` (payload = ServiceStatus string) and `ocr://log`. Invoked from the frontend with `invoke("command_name", {...})` from `@tauri-apps/api/core`. Command args are camelCase in JS and snake_case in Rust; serde structs serialize **camelCase** as well (the TS field is `pdfPath`, not `pdf_path`).
- OCR scheduling bridge (stage 4 批3): the parse store drives the loop entirely frontend-side — single `tick()` = pick book (focused first; per-book `load_pdf` reads bind JSON status/finished flags, no parse_progress command) → ring-collect ≤4 unfinished pages (focused book starts at `reader.currentPage`, others at 1) → `src/lib/pageCapture.ts` offscreen render (PNG b64, scale 2.0) → invoke `parse_pdf` → patch `library.pdfs[id].pages` for the focused book (translation pane updates reactively; background books have no store cache — Rust's atomic tmp+rename batch write is the truth, next round re-reads via load_pdf). The chain self-continues via queueMicrotask after each batch; nothing processable → `standing` suspends; wakes fire from library.selectPdf / importPdf success / loadRepo / serviceStatus→connected watch / unpause / prefill completion. Batch failure: per-book strike map, 3 strikes = skip that book until next wake. `usePdfDoc` is LRU≤2 with a pin for the focus book (never evicted); background books reuse the same per-id cache. Books with empty pages (lopdf parse failure) are skipped until opened — geometry-ready watch backfills via `prefill_pages` then wakes. Non-Tauri browser mode (`pnpm dev` without Tauri): silently inert.
- `src-tauri/bindings/` — ts-rs generated by `cargo test`; never hand-edit, and delete stale files when a type is removed.
- `src-tauri/capabilities/default.json` — permission allowlist. New Tauri plugin APIs won't work until their permissions are added here.
- `src-tauri/gen/` — generated schemas; never hand-edit.

## Gotchas

- **Port 1420 is strict** (`vite.config.ts`): Vite fails if it's taken, and `tauri.conf.json` points `devUrl` at it. HMR uses 1421 when `TAURI_DEV_HOST` is set.
- **`testfiles/` is gitignored** and reserved for manual-test PDFs (text+table+formula+image). It is no longer referenced by code; the reader renders PDFs from the library store (real repo data via IPC only — mock data was removed).
- **Asset protocol** (`tauri.conf.json` → `security.assetProtocol`): enabled with an intentionally **empty static scope**; `gettree_from_config` grants the repo root at runtime via `asset_protocol_scope().allow_directory(root, true)` (least privilege). Requires the `protocol-asset` cargo feature on `tauri` (already set). If a render shows "PDF 加载失败", suspect a missing scope grant first.
- **pdfjs v6 API breaks**: `PDFDocumentProxy.destroy()` no longer exists — release via `doc.loadingTask.destroy()`; `page.render()` requires `canvas` (not just `canvasContext`).
- **pdfjs runtime assets** (`cmaps`/`standard_fonts`/`wasm`/`iccs`) are copied to `public/pdfjs/` by `scripts/copy-pdfjs-assets.mjs` (runs at the start of `pnpm dev`/`pnpm build`). `public/pdfjs/` is gitignored — regenerated on first dev/build, never hand-edit. Without them CJK text renders misplaced/missing.
- Vite is configured to not watch `**/src-tauri/**` — Rust changes require restarting `pnpm tauri dev`.
- Windows dev machine: the Rust lib is named `ezpdf_lib` (with `_lib` suffix) to avoid a Windows bin/lib name conflict — keep the suffix.
- TypeScript is strict with `noUnusedLocals`/`noUnusedParameters`; unused imports will fail `pnpm build`.
- No CSP is set (`"csp": null` in `tauri.conf.json`) — fine for dev; if a CSP is added later, pdfjs needs `worker-src` for its module worker.
- The build warning about a >500 kB chunk is expected (pdfjs-dist is large); code-split later if it matters.
- Legacy hand-written test entries in a repo (files not named `<name>-<id>.pdf`) will fail to load/render by design — re-import them.
- Running `vite` directly (not via `pnpm dev`/`pnpm build`) skips the pdfjs asset copy — a fresh clone then misses `public/pdfjs/` and CJK rendering degrades (404s in console, no crash).
- **pyserver/** is the ported Wise-Paddle OCR service host (stage 2.5; decisions in PLAN-pyserver.md §2.1). Single-instance pipeline (`PP-DocLayoutV3` + `PaddleOCR-VL-1.6` in `app/services/pipeline.py`, lazy-loaded + `threading.Lock`) — concurrency containers (Pool/Scheduler/vouchers) were deliberately degenerated away; don't reintroduce them. `models/` is a direct copy of Wise-Paddle's model dir (1.9GB, gitignored) but is not a hard prerequisite — on a fresh host `app/fetch.py` (`python -m app.fetch`, invoked by `ocr_download_models`) downloads the missing repos via hf-mirror with resume; completeness = config.json + preprocessor_config.json + any weight file (same contract as bootstrap.py). `requirements-download.txt` is `huggingface_hub` only, installed on demand. `requirements.txt` is a verified-minimal set; the four non-obvious pins are load-path requirements, not optional: `protobuf` (SentencePieceExtractor; without it the VL tokenizer is misdetected as a tiktoken file and fails to parse), `sentencepiece` + `tiktoken` (PaddleOCR-VL tokenizer), `opencv-contrib-python` (PP-DocLayoutV3 post-processing). The VL tokenizer loads without `trust_remote_code` — the rope patch in `pipeline.py` (ported, module-level side effect) must stay. Layout detection is multi-pass add-only (`LayoutDetector.detect`): main pass unchanged at threshold 0.5, then a sharpened pass at 0.45 merges text-family candidates, then sharpened top/bottom half-page tiles at 0.38 (header/footer also allowed) merge more — fixes systematic misses of small/spaced text under pdfjs rendering (pdfium renders score ~0.1-0.15 higher on the same line; full-page squash to 800x800 compresses tall pages, tiles undo it; tuned 2026-09-12, see PLAN-OCR.md §8.4; candidates must pass IoU ≤0.3 and containment ≤0.6 against existing boxes; `BoxFilter.min_score` is 0.35 to let them through; all model forwards are chunked to ≤4 images because batch=8 hits a slow kernel).
- `parse.ts` store: `serviceStatus` (incl. `failed`) is driven by the `ocr://status` event, `envReport`/`envLogs` by `ocr_env_report`/`ocr://log`; the OCR settings pane's five lights (Python/CUDA/环境/模型/服务) derive from these — don't add separate probe commands. 模型灯未就绪时「下载模型」按钮触发 `ocr_download_models`（`modelsBusy` 防重入）。
- Frontend `listen()` subscriptions in `parse.ts` reject silently outside the Tauri runtime (plain `pnpm dev` browser mode) — keep the `.catch(() => undefined)`.
